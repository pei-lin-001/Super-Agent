## 修改与根因

`create_task` 支持按已登记产物 ID 显式传入固定版本；Router 使用真实调用上下文核对会话与话题，复制时校验文件路径、大小和 SHA-256。快照放在新任务 `inputs/`，文件工具禁止直接修改，旧检查结论不随快照转移。`read_task` 返回 ID、文件名、版本与指纹供 Router 选择。历史任务与新任务仍是独立任务，不增加跨任务浏览接口。进程工具仍具有用户权限。

证据表明，旧任务产物缺少受控交接会迫使模型自行寻找路径；该问题有直接机制对照。首轮报告中的置信度升级发生在综合与交付阶段：工作记录曾保留“档案自述、缺数据、未核对”等条件，报告和 Router 行动建议未始终带上条件。模型自身判断能力与压缩过程均可能影响结果，现有记录不足以唯一确定原因。只在负责人引导中补充关键行动依据、来源和适用条件应一起保留，并允许缩小结论、补证或寻求判断；同一版本同时包含交接与提示修改，因此不能把模型表述变化归因于单项修改。Router 仍可能把“结合资料”强化成“通读”，但本次不能仅凭措辞或步数证明无效穷举。
